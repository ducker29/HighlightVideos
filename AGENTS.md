# Инструкции для агента — HighlightVideos

## Контекст проекта и проверка рабочей папки

- Этот репозиторий — **HighlightVideos**, локальное Python/Tkinter-приложение для анализа YouTube VOD, ручного ревью и нарезки горизонтальных хайлайтов.
- Текущий корень проекта: `D:\Dev\HighlightVideos`. При переносе репозитория ориентируйся на фактический корень рабочей области.
- В начале сеанса прочитай этот файл, проверь содержимое корня и `git status --short`. Перед изменениями изучи относящиеся к задаче модули.
- Инструкции про Unreal Engine, DroneSim58, Blueprint, Unreal MCP или Blender относятся к другим проектам и не являются рабочим процессом этого репозитория.
- Не открывай `D:\UnrealProjects\DroneSim58` и другие внешние проекты по шаблону из глобальных инструкций. Обращайся к внешним проектам только при явной связи с текущей задачей пользователя.
- Не предполагай наличие ассетов, сервисов, инструментов или файлов: проверяй фактическое состояние текущего проекта.
- Общайся с пользователем по-русски.

## Строгое правило Git

**Запрещено делать коммиты и push без явного разрешения пользователя.**

- Просьбы «исправь», «реализуй», «продолжай» и аналогичные не являются разрешением на commit или push.
- Разрешение на commit не означает разрешение на push; разрешение на push не означает разрешение на создание новых коммитов.
- Не делай amend, force-push, не меняй историю и настройки Git без отдельного явного разрешения.
- До разрешённого коммита проверь `git status`, `git diff` и последние сообщения коммитов; включай только относящиеся к задаче файлы. Не коммить секреты.
- Не удаляй и не перезаписывай посторонние изменения пользователя.

## Документация и источники контекста

- `LOCAL_SETUP.md` — актуальные установка, запуск, работа интерфейса, запас в конце, отчёты, кеширование и ограничения.
- `Highlight_Video_Pipeline.md` — постановка задачи и архитектура пайплайна; читай соответствующие задаче разделы.
- `README.md` содержит также описание исходного Colab-проекта для вертикальных Shorts. Не принимай его устаревшие примеры за текущий сценарий приложения.
- Сопоставляй документацию с реализацией; обнаруженные расхождения обозначай явно.

## Карта реализации

- `main.py` — точка входа; поддерживает `--report` для открытия сохранённого отчёта.
- `start_gui.bat` — запуск интерфейса в Windows.
- `review_ui.py` — Tkinter-интерфейс, таблица кандидатов, правки, утверждение и запуск нарезки.
- `app_backend.py` — оркестрация скачивания, ASR, анализа, редакторской проверки и открытия отчётов.
- `downloader.py` — yt-dlp и проверка медиа через ffprobe.
- `transcriber.py`, `gpu_runtime.py` — ASR и локальная подготовка CUDA.
- `analyzer.py`, `llm_context.py` — анализ через Ollama HTTP, кеш и бюджет контекста.
- `interval_builder.py`, `interval_selector.py` — построение допустимых интервалов и выбор моделью.
- `editorial_review.py` — отдельная редакционная проверка кандидатов.
- `clip_padding.py` — подготовка отчёта с запасом в конце.
- `transcript_review.py`, `ui_editing.py` — контекст транскрипта и редактирование в UI.
- `renderer.py` — рендер утверждённых интервалов, имена выходных файлов и проверка результата.
- `job_store.py` — JSON, таймкоды, валидация интервалов и диапазона анализа.
- `config.json` — настройки приложения; `data/` — исходники, модели, транскрипты, кеш, отчёты и результаты.
- `pipeline.py`, `clip_renderer.py`, `ollama.py`, `link_drive.py` — исходные Colab-скрипты, не используемые локальным приложением. Локальный `ollama.py` не является клиентом текущего приложения.

## Инварианты при изменениях

- Анализ создаёт кандидатов, но не запускает финальную нарезку автоматически. Финальные интервалы утверждает пользователь.
- Рендер сохраняет полный горизонтальный кадр и разрешение источника, без вертикального кропа и добавления субтитров.
- Изменение утверждённых границ требует повторного утверждения; соблюдай проверку `approval_key`.
- Таблица, предпросмотр и рендер должны использовать одинаковые итоговые границы. Не добавляй скрытый запас только на этапе рендера.
- Запас должен считаться от базовой границы, без накопления при повторном применении. Учитывай ручные правки, ограничения длительности и конец источника.
- Сохраняй совместимость существующих отчётов, ручные решения, кеш и ранее созданные MP4. Не запускай повторные ASR/LLM/скачивание без необходимости для задачи.
- Не удаляй данные, модели, отчёты и результаты пользователя без явного запроса.
- При изменении пользовательского поведения актуализируй соответствующий раздел `LOCAL_SETUP.md`; архитектурные изменения отражай в `Highlight_Video_Pipeline.md`.

## Запуск и проверки

Команды выполняются из корня репозитория в PowerShell:

```powershell
.\.venv\Scripts\python.exe main.py
.\.venv\Scripts\python.exe -m unittest discover -v
```

- Используй существующую `.venv`, если она доступна.
- Выбирай проверки по изменённой логике: `test_pipeline.py`, `test_intervals.py`, `test_transcript_review.py`, `test_ui_editing.py`.
- Проверки с реальным скачиванием, GPU или Ollama (`gpu_smoke_test.py`, `validate_vod.py` и диагностические утилиты) запускай осмысленно: они могут требовать сервисов, больших файлов и длительного выполнения.
- Для изменений интерфейса проверяй затронутое поведение и сообщай, если визуальная проверка не выполнялась.
- В результате работы перечисли сделанное, выполненные проверки и оставшиеся ограничения, если они есть.
