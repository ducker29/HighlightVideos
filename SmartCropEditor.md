# Техническое задание: Smart Crop Editor для HighlightVideos

## 1. Цель

Реализовать отдельный графический редактор **Smart Crop Editor** для настройки вертикального кадрирования утверждённых Shorts.

Исходное видео — горизонтальное 16:9. Результат — вертикальное 9:16, в котором отображается только один участник интервью.

Редактор должен позволять:
- автоматически определять и кадрировать одиночные планы;
- вручную выбирать ведущего или гостя на split-screen;
- менять кадрирование в произвольный момент;
- видеть реальный предпросмотр результата;
- сохранять настройки для последующего рендера;
- повторно открывать и редактировать сохранённые настройки.

**Важно:** Smart Crop запускается исключительно после утверждения Shorts. Не изменять этапы транскрипции, анализа, отбора кандидатов и их оценки.

## 2. Сначала изучить проект

Перед реализацией:

1. Изучить существующую архитектуру HighlightVideos.
2. Найти код интерфейса утверждения Shorts.
3. Изучить `renderer.py` и существующий процесс рендера.
4. Выяснить, где хранятся границы утверждённых Shorts, их идентификаторы и пути к видео.
5. Определить используемый GUI-фреймворк и способ воспроизведения видео.

Не создавать параллельную архитектуру приложения.

Использовать существующие зависимости, если они подходят. Новые библиотеки добавлять только при необходимости.

## 3. Архитектура

Разделить реализацию на независимые компоненты:

**SmartCropAnalyzer**
- Анализирует только выбранный фрагмент.
- Определяет смены монтажных планов.
- Находит лица и их координаты.
- Формирует предварительные интервалы кадрирования.
- Не выполняет рендер.

**SmartCropEditor**
- Отдельное GUI-окно.
- Показывает исходное видео и вертикальный предпросмотр.
- Позволяет редактировать интервалы.
- Сохраняет настройки.

**SmartCropRenderer**
- Преобразует интервалы кадрирования в команды существующего FFmpeg-рендерера.
- Не дублирует существующую логику субтитров, звука и экспорта.

Названия компонентов можно адаптировать под архитектуру проекта.

## 4. Типы планов

Поддержать следующие типы:

| Тип | Описание |
|---|---|
| HOST_MEDIUM | Ведущий, средний или близкий план |
| HOST_CLOSE | Ведущий, суперблизкий план |
| GUEST_MEDIUM | Гость, средний план |
| GUEST_CLOSE | Гость, крупный план |
| SPLIT | Оба участника одновременно |
| INSERT | Иллюстративная вставка |
| UNKNOWN | Неопределённый план |

Ведущий обычно находится слева на split-screen, гость — справа.

Для одиночных планов выбирать видимого участника независимо от того, кто говорит в аудио.

Для SPLIT на первом этапе использовать ручной выбор участника.

Для INSERT и UNKNOWN не выполнять случайное переключение. Использовать безопасный режим предпросмотра и явно показывать, что интервал требует проверки.

## 5. Автоматическое определение планов

Предыдущий эксперимент с `analyze_shots.py` выявил проблему: за 97 минут было найдено только семь планов. Не использовать его результаты как достоверные.

Разработать отдельную детекцию монтажных переходов для коротких утверждённых Shorts.

Требования:
- анализировать только утверждённый временной диапазон с небольшим запасом;
- использовать облегчённые кадры для анализа;
- не пропускать реальные переключения камер;
- сохранять точные таймкоды переходов;
- не принимать движение рук или мимику за монтажную склейку;
- предусмотреть ручную коррекцию ошибок.

Можно использовать PySceneDetect либо FFmpeg, но сначала сравнить результаты на коротком тестовом фрагменте.

Не добавлять тяжёлые нейросети без подтверждённой необходимости.

## 6. Определение лиц и кадрирование

Для каждого обнаруженного плана:

1. Найти лицо или лица.
2. Определить тип плана.
3. Выбрать целевого участника.
4. Рассчитать область кадрирования 9:16.
5. Проверить, что голова и лицо не обрезаны.
6. Сохранить координаты crop.

Кадрирование должно учитывать:
- положение лица;
- размер головы;
- пространство над головой;
- положение плеч;
- границы исходного кадра;
- различия между крупным и средним планом.

Для статичного плана предпочтительно стабильное кадрирование без постоянного движения окна.

На split-screen должны существовать две независимые конфигурации: HOST и GUEST.

Не допускать попадания второго человека в итоговый вертикальный кадр, насколько это позволяет исходная композиция.

Если геометрически невозможно получить корректный кадр 9:16 без второго участника, пометить интервал для ручной проверки.

## 7. Отдельный GUI-редактор

Открывать Smart Crop Editor из существующего интерфейса через действие «Настроить кадрирование».

Не перегружать основное окно дополнительными панелями.

Редактор должен содержать:

**Левая область**
- Исходное видео 16:9.
- Видимая рамка текущего crop.
- Возможность перетаскивать рамку мышью.
- Возможность изменять масштаб кадрирования.

**Правая область**
- Вертикальный предпросмотр 9:16.
- Предпросмотр должен соответствовать фактическому результату рендера.
- При перемещении по таймлайну кадр обновляется.

**Нижняя область**
- Таймлайн Shorts.
- Отображение границ монтажных планов.
- Цветные интервалы HOST/GUEST.
- Отдельное обозначение SPLIT/UNKNOWN/INSERT.
- Текущая позиция воспроизведения.
- Возможность выбора и редактирования интервала.

**Панель управления**
- Ведущий.
- Гость.
- Автоматически.
- Разделить интервал.
- Объединить интервалы.
- Удалить ручное переопределение.
- Сбросить кадрирование.
- Сохранить.

Не создавать фиктивные элементы управления: все кнопки должны выполнять соответствующие действия.

## 8. Горячие клавиши

Поддержать:

- `Space` — воспроизведение/пауза.
- `1` — выбрать ведущего.
- `2` — выбрать гостя.
- `Left/Right` — перемещение по таймлайну.
- `Shift + Left/Right` — переход между границами интервалов.
- `S` — разделить интервал в текущей позиции.
- `Ctrl + S` — сохранить.
- `Ctrl + Z` — отменить изменение.
- `Ctrl + Y` — повторить изменение.

Горячие клавиши не должны конфликтовать с полями ввода.

## 9. Ручное переключение на split-screen

Это ключевой сценарий.

Пример:

- 00:00–00:08 — говорит ведущий.
- 00:08–00:15 — говорит гость.
- 00:15–00:20 — говорит ведущий.

Если исходный план всё это время SPLIT, пользователь должен иметь возможность установить:

- 00:00–00:08 → HOST
- 00:08–00:15 → GUEST
- 00:15–00:20 → HOST

Переключение crop должно происходить мгновенно, без анимации.

Разрешить переключение внутри одного непрерывного монтажного плана.

Границы интервалов должны редактироваться с точностью до видеокадра.

## 10. Хранение настроек

Создать отдельный JSON-файл настроек для каждого утверждённого Shorts.

Пример структуры:

```json
{
  "schema_version": 1,
  "candidate_id": "sc003",
  "source_start": 1450.0,
  "source_end": 1505.0,
  "output_aspect_ratio": "9:16",
  "segments": [
    {
      "start": 0.0,
      "end": 8.0,
      "shot_type": "HOST_MEDIUM",
      "target": "HOST",
      "crop": {
        "x": 340,
        "y": 0,
        "width": 608,
        "height": 1080
      },
      "manual_override": false
    },
    {
      "start": 8.0,
      "end": 15.0,
      "shot_type": "SPLIT",
      "target": "GUEST",
      "crop": {
        "x": 1200,
        "y": 0,
        "width": 608,
        "height": 1080
      },
      "manual_override": true
    }
  ]
}
```

Это пример формата, а не реальные координаты.

Требования:
- время сегментов относительно начала Shorts;
- координаты crop в системе координат исходного видео;
- интервалы не должны пересекаться;
- интервалы должны покрывать весь Shorts;
- crop всегда должен оставаться внутри изображения;
- сохранять ручные изменения отдельно от автоматических предложений;
- сохранять настройки атомарно;
- поддерживать повторное открытие.

Не использовать только `candidate_id` для идентификации файла: предусмотреть уникальность в рамках исходного видео и устойчивость к повторному анализу.

## 11. Интеграция с рендерером

После сохранения настроек существующий рендерер должен иметь возможность использовать Smart Crop.

Требования:
- применять crop к исходному видео высокого качества, не к 720p-копии;
- сохранять существующую обработку аудио;
- сохранять существующие субтитры;
- не нарушать Windows-совместимость FFmpeg;
- не менять поведение старого рендера, если Smart Crop отключён;
- переключать crop точно на границах интервалов;
- избегать рассинхронизации звука и изображения.

Предусмотреть включение/выключение Smart Crop.

Если файл настроек отсутствует, использовать прежний способ рендера.

Не выполнять полный рендер из GUI-потока.

## 12. Проверки и обработка ошибок

Предусмотреть:
- отсутствие исходного видео;
- повреждённый JSON;
- несовпадение длительности;
- пустые или перекрывающиеся интервалы;
- выход crop за границы;
- отсутствие найденных лиц;
- неверно определённый тип плана;
- невозможность декодирования видео;
- закрытие редактора с несохранёнными изменениями.

Не допускать зависания GUI при анализе или воспроизведении.

При ошибке автоматического анализа сохранять возможность ручной настройки.

## 14. Порядок реализации

**Этап A — независимый прототип**

Реализовать:
- отдельное окно;
- загрузку утверждённого фрагмента;
- исходный и вертикальный предпросмотр;
- ручную настройку crop;
- редактирование временных интервалов;
- сохранение и загрузку JSON.

На этом этапе допускается ручное создание интервалов без автоматической классификации планов.

**Этап B — автоматическое предложение crop**

Добавить:
- обнаружение монтажных склеек;
- распознавание одиночных и split-screen планов;
- поиск лиц;
- предварительный расчёт crop;
- пометки для ручной проверки.

**Этап C — интеграция с рендерером**

Добавить:
- чтение сохранённых настроек;
- применение динамического crop через FFmpeg;
- совместимость с субтитрами;
- интеграционные тесты;
- возможность отключения Smart Crop.

Не переходить к следующему этапу без успешной проверки предыдущего.
