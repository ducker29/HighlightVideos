# Автоматический пайплайн создания хайлайтов из разговорных YouTube-стримов

Репозиторий изначального образца:
https://github.com/RMIN06/Ai-Clipping-Tool-fast-whisper

## 1. Задача

Нужно автоматически обрабатывать длинные YouTube VOD — разговорные стримы, где автор на камеру рассказывает на интересные темы.

Цель:
- скачать VOD;
- получить точный транскрипт с таймкодами;
- найти смысловые фрагменты, пригодные для отдельных хайлайтов;
- объединить фрагменты одной темы в законченный интервал;
- вырезать **горизонтальные 16:9 клипы** длительностью **2–5 минут**, иногда до 6–8 минут;
- не делать вертикальные Shorts;
- не обрезать мысль на середине;
- сохранить исходное качество и формат видео;
- выдать человеку список кандидатов для быстрого утверждения перед финальным рендером.

Формат контента:
- один основной говорящий;
- камера статичная или почти статичная;
- визуальные события, геймплей и движение не являются главным сигналом;
- главный сигнал — речь: темы, истории, аргументы, эмоции, неожиданные выводы.

## 2. Важные ограничения

1. Нельзя нарезать транскрипт только по фиксированным 2–3 минутам и сразу отдавать LLM.
   Одна тема может длиться 10–20 минут, и её смысл будет разорван.

2. Нельзя просить LLM обработать весь 8-часовой транскрипт одним запросом.
   Это дорого, медленно и ненадёжно.

3. Нельзя доверять LLM выдуманным таймкодам.
   Модель может использовать только таймкоды, реально присутствующие в транскрипте.

4. Нельзя делать вертикальный кроп.
   Итоговые видео должны оставаться в исходном горизонтальном формате 16:9.

5. Нельзя автоматически публиковать клипы без ревью.
   LLM должна находить кандидатов, а человек утверждает финальные интервалы.

## 3. Общая архитектура

```text
YouTube VOD URL
      ↓
yt-dlp
      ↓
Исходное видео 16:9
      ↓
FFmpeg → извлечение аудио
      ↓
faster-whisper / WhisperX
      ↓
Транскрипт: предложения + word-level timestamps
      ↓
Грубая сегментация: окна по 120–180 секунд, overlap 20–40 секунд
      ↓
LLM PASS 1: анализ каждого окна
      ↓
Semantic merge: склейка соседних окон одной темы
      ↓
LLM PASS 2: выбор точного интервала внутри тематического блока
      ↓
Дедупликация и ranking кандидатов
       ↓
Редакционная проверка кандидатов с контекстом ДО / КЛИП / ПОСЛЕ
       ↓
Review UI / JSON-отчёт для человека
      ↓
FFmpeg: точная нарезка исходного 16:9 видео
      ↓
Готовые горизонтальные хайлайты
```

Подход map-reduce масштабируется на длинные документы: сначала каждая часть обрабатывается независимо, затем результаты объединяются в общий результат. [56][58]

## 4. Технологический стек

| Этап | Инструмент | Назначение |
|---|---|---|
| Скачивание | `yt-dlp` | Скачать YouTube VOD и метаданные |
| Аудио | `FFmpeg` | Извлечь аудио, нормализовать при необходимости |
| Транскрипция | `faster-whisper` или `WhisperX` | Получить текст с таймкодами |
| VAD | Silero VAD через faster-whisper | Отфильтровать тишину |
| LLM | Ollama + Qwen / Llama / другая локальная модель | Анализ, резюме, отбор, объединение тем |
| Embeddings | Локальная embedding-модель | Найти смены темы и похожие фрагменты |
| Нарезка | `FFmpeg` | Вырезать клипы из исходного видео |
| Очередь и хранение | SQLite или JSON-файлы | Статусы, кандидаты, решения человека |
| UI | Tkinter (локальное Windows-приложение) | Ввод ссылки и длительности, просмотр и утверждение кандидатов |

`faster-whisper` поддерживает `word_timestamps=True` и VAD-фильтрацию тишины, что важно для точной привязки найденных LLM границ к реальному времени видео. [64][66]

## 7. Этап 1 — скачивание VOD

### Команда

```bash
yt-dlp \
  -f "bv*+ba/b" \
  --merge-output-format mp4 \
  -o "data/videos/%(id)s.%(ext)s" \
  "YOUTUBE_URL"
```

### Требования

- сохранить исходное разрешение;
- сохранить исходную частоту кадров;
- не делать вертикальный кроп;
- сохранить метаданные: title, upload_date, duration, id.

## 8. Этап 2 — извлечение аудио

```bash
ffmpeg -y \
  -i "data/videos/VIDEO.mp4" \
  -vn \
  -ac 1 \
  -ar 16000 \
  -c:a pcm_s16le \
  "data/audio/VIDEO.wav"
```

Моно-аудио 16 kHz достаточно для Whisper и уменьшает размер файла.

## 9. Этап 3 — транскрипция

Использовать `faster-whisper`:

```python
from faster_whisper import WhisperModel

model = WhisperModel(
    "large-v3",
    device="cuda",
    compute_type="float16"
)

segments, info = model.transcribe(
    "data/audio/VIDEO.wav",
    language="ru",
    word_timestamps=True,
    vad_filter=True,
    vad_parameters={
        "min_silence_duration_ms": 500
    }
)
```

`faster-whisper` возвращает сегменты и слова с временными метками; VAD помогает убрать длинные паузы без речи. [64][66]

### Формат транскрипта

Сохранять в JSON:

```json
{
  "video_id": "abc123",
  "language": "ru",
  "duration_sec": 28800,
  "segments": [
    {
      "id": 0,
      "start": 0.0,
      "end": 6.42,
      "text": "Сегодня я хочу разобрать одну важную тему.",
      "words": [
        {
          "start": 0.0,
          "end": 0.42,
          "word": "Сегодня"
        }
      ]
    }
  ]
}
```

Также сохранить человекочитаемый SRT или VTT для review UI.

## 10. Этап 4 — грубая сегментация

Сегментация происходит **до LLM**, но это только технические окна, а не финальные хайлайты.

Правила:

- окно: 120–180 секунд;
- перекрытие: 20–40 секунд;
- резать предпочтительно по границе предложения;
- не резать посреди слова;
- каждому окну присвоить `window_id`, `start`, `end`;
- в начало каждого окна добавлять краткое резюме предыдущего окна;
- в конец каждого окна добавлять первые 1–2 предложения следующего окна как контекст.

Пример:

```text
Window 12:
  start: 01:22:10
  end:   01:24:40
  overlap_from_previous: 30 sec
  context_from_next: 15 sec
```

Перекрытие нужно, чтобы сильная фраза или начало истории, попавшие на границу, не потерялись. [34][37]

## 11. Этап 5 — LLM PASS 1: анализ окон

На этом этапе LLM **не выбирает финальный клип**.

Она анализирует каждое техническое окно и возвращает метаданные для последующего объединения.

### Промпт PASS 1

```text
Ты опытный редактор YouTube-канала.

Формат видео: автор в кадре рассказывает на интересные темы.
Это НЕ игровой стрим, НЕ влог с событиями и НЕ короткий формат.
Главный сигнал интересности — содержание речи.

Ниже приведён один фрагмент транскрипта с таймкодами.
Это техническое окно, а не готовый хайлайт.

Твоя задача:
1. Кратко описать, о чём говорится в окне.
2. Определить основную тему.
3. Определить, продолжается ли тема из предыдущего окна.
4. Определить, продолжается ли тема в следующем окне.
5. Оценить потенциал окна как будущего хайлайта.
6. Найти сильные фразы, истории, споры, неожиданные факты, эмоции или полезные выводы.
7. Указать, является ли мысль внутри окна законченной.

Не выдумывай таймкоды.
Используй только таймкоды из транскрипта.

Критерии интересности:
- неожиданный факт или контринтуитивный вывод;
- личная история с завязкой и результатом;
- спор, критика, сильное мнение;
- практический совет или объяснение сложной темы;
- эмоциональный момент: удивление, возмущение, смех;
- самодостаточность: фрагмент можно понять без остального стрима;
- сильный hook в первые 10–30 секунд.

Верни строго валидный JSON без markdown и без пояснений.

Формат ответа:
{
  "window_id": "string",
  "start": "HH:MM:SS",
  "end": "HH:MM:SS",
  "topic": "краткое название темы",
  "summary": "2–4 предложения о содержании окна",
  "continues_previous": true,
  "continues_next": true,
  "self_contained": false,
  "interest_score": 0,
  "hook_score": 0,
  "emotion_score": 0,
  "information_score": 0,
  "strong_moments": [
    {
      "start": "HH:MM:SS",
      "end": "HH:MM:SS",
      "quote": "точная цитата из транскрипта",
      "reason": "почему это сильно"
    }
  ],
  "possible_clip_boundaries": {
    "best_start": "HH:MM:SS",
    "best_end": "HH:MM:SS",
    "reason": "почему эти границы подходят"
  },
  "problems": [
    "длинные паузы",
    "повторы",
    "обрыв мысли",
    "технические проблемы",
    "слишком много контекста из предыдущей темы"
  ]
}

Предыдущее окно, summary:
{{PREVIOUS_WINDOW_SUMMARY}}

Следующее окно, первые предложения:
{{NEXT_WINDOW_CONTEXT}}

Транскрипт окна:
{{WINDOW_TRANSCRIPT_WITH_TIMESTAMPS}}
```

## 12. Этап 6 — semantic merge

После PASS 1 нужно объединить последовательные окна одной темы.

### Правила объединения

Окна A, B, C объединяются в один тематический блок, если выполняется хотя бы одно:

- `B.continues_previous == true`;
- embedding последнего предложения A и первого предложения B имеют similarity >= 0.72;
- `topic` окон совпадает или почти совпадает;
- LLM в PASS 2 подтверждает, что это одна линия рассуждения.

### Пример

```text
w_013: topic = "Ограничения локальных LLM", continues_next = true
w_014: topic = "Ограничения локальных LLM", continues_previous = true, continues_next = true
w_015: topic = "Ограничения локальных LLM", continues_previous = true, self_contained = true
```

Результат:

```text
topic_block_004:
  windows: [w_013, w_014, w_015]
  start: 01:19:40
  end: 01:29:20
  topic: "Ограничения локальных LLM"
```

## 13. Этап 7 — LLM PASS 2: выбор точного клипа

Теперь LLM получает не отдельное окно, а весь тематический блок в виде summaries и сильных моментов.

Её задача — выбрать **лучший непрерывный подинтервал** длительностью 2–5 минут.

### Промпт PASS 2

```text
Ты главный редактор YouTube-канала.

Ниже — несколько последовательных окон одного разговорного видео.
Они могут относиться к одной теме или содержать переход к другой теме.

Твоя задача:
1. Определить, действительно ли это одна связная тема.
2. Найти лучший непрерывный интервал для отдельного YouTube-хайлайта.
3. Длительность клипа должна быть от {{MIN_DURATION}} до {{MAX_DURATION}} секунд.
4. Клип должен начинаться с понятного hook.
5. Клип должен заканчиваться на завершённой мысли, выводе или естественной точке.
6. Не обрезай историю или аргумент на середине.
7. Если тема длиннее допустимого клипа, выбери самый сильный самодостаточный подинтервал.
8. Если тема слишком слабая, верни пустой массив.

Запрещено:
- выдумывать таймкоды;
- объединять несмежные интервалы;
- выбирать интервал, который начинается или заканчивается посреди незавершённой мысли;
- делать клип короче {{MIN_DURATION}} секунд или длиннее {{MAX_DURATION}} секунд.

Верни строго валидный JSON без markdown.

Формат ответа:
[
  {
    "topic_block_id": "string",
    "start": "HH:MM:SS",
    "end": "HH:MM:SS",
    "duration_sec": 0,
    "score": 0,
    "title": "короткий кликабельный заголовок",
    "hook": "первые 1–2 предложения клипа",
    "reason": "почему это сильный хайлайт",
    "clip_type": "story|insight|opinion|debate|funny|emotional",
    "needs_context_before": false,
    "needs_context_after": false,
    "warnings": []
  }
]

Настройки:
MIN_DURATION = {{MIN_DURATION}}
MAX_DURATION = {{MAX_DURATION}}

Данные тематического блока:
{{TOPIC_BLOCK_JSON}}

Полный транскрипт блока:
{{TOPIC_BLOCK_TRANSCRIPT}}
```

## 14. Этап 8 — дедупликация и ranking

После PASS 2 может возникнуть несколько кандидатов с пересекающимися интервалами.

### Правила

1. Рассчитать IoU пересечения кандидатов:

```text
IoU = intersection_duration / union_duration
```

2. Если `IoU >= 0.35`, оставить кандидата с более высоким `score`.

3. Отсортировать по:

```text
final_score =
    0.50 * llm_score
  + 0.20 * hook_score
  + 0.15 * information_score
  + 0.10 * emotion_score
  + 0.05 * self_contained_bonus
```

4. Оставить top-N уникальных кандидатов.

5. Добавить буфер:

```text
final_start = candidate_start - 3 sec
final_end   = candidate_end + 5 sec
```

Буфер нужен, чтобы не обрезать первое или последнее слово.

## 15. Этап 9 — ревью человеком

Система должна сформировать review-отчёт:

```json
{
  "video_id": "abc123",
  "candidates": [
    {
      "candidate_id": "c_001",
      "start": "01:21:12",
      "end": "01:26:45",
      "duration_sec": 333,
      "score": 88,
      "title": "Почему локальная LLM не заменит облачную для больших проектов",
      "reason": "Законченное рассуждение с примером и выводом.",
      "preview_url": "http://localhost:8000/preview/c_001",
      "status": "pending"
    }
  ]
}
```

Review UI должен позволять:

- открыть превью с точным таймкодом;
- посмотреть транскрипт кандидата;
- сдвинуть start/end на ±1, ±5, ±15 секунд;
- одобрить, отклонить или пометить «нужна доработка»;
- изменить заголовок;
- запустить рендер только одобренных клипов.

## 16. Этап 10 — нарезка видео

Для чернового быстрого рендера можно использовать stream copy:

```bash
ffmpeg -y \
  -ss "01:21:12" \
  -to "01:26:45" \
  -i "data/videos/VIDEO.mp4" \
  -map 0 \
  -c copy \
  "data/output/draft_c_001.mp4"
```

`-c copy` копирует видео- и аудиопотоки без перекодирования, поэтому нарезка быстрая, но граница может попасть не идеально точно на ключевой кадр. [65][68]

Для финального高质量 рендера использовать перекодирование:

```bash
ffmpeg -y \
  -ss "01:21:12" \
  -to "01:26:45" \
  -i "data/videos/VIDEO.mp4" \
  -map 0:v:0 -map 0:a:0 \
  -c:v libx264 \
  -preset slow \
  -crf 18 \
  -c:a aac \
  -b:a 192k \
  "data/output/final_c_001.mp4"
```

Требования:

- **не добавлять** `crop`;
- **не менять** соотношение сторон;
- сохранять исходное разрешение;
- сохранять горизонтальный формат 16:9;
- при необходимости добавить только обычные нижние субтитры.

## 20. Дополнительные сигналы

LLM-анализ должен быть основным, но можно добавить лёгкие аудио-метрики.

| Сигнал | Как считать | Как использовать |
|---|---|---|
| RMS energy | Скользящее окно 1–3 секунды | Находить эмоциональные пики |
| Speech rate | Количество слов в минуту | Ускорение часто совпадает с акцентом |
| Паузы | VAD / silence detection | Длинные паузы — минус для клипа |
| Смех | Аудио-классификатор или ручная разметка | Усиливает funny/reaction-кандидатов |
| Повторы | N-граммы / embeddings | Штрафовать повторяющиеся мысли |

Формула:

```text
audio_bonus =
    0.4 * energy_peak
  + 0.3 * speech_rate_change
  + 0.2 * laughter
  - 0.3 * long_silence_penalty
```

Итоговый score:

```text
final_score =
    0.60 * llm_score
  + 0.20 * hook_score
  + 0.10 * information_score
  + 0.10 * audio_bonus
```

## 21. Ошибки, которые нужно предотвращать

| Проблема | Причина | Решение |
|---|---|---|
| LLM режет тему посередине | Фиксированные окна без semantic merge | PASS 1 + PASS 2 + embeddings |
| Дубликаты кандидатов | Overlap и несколько проходов | IoU-дедупликация |
| Неверные таймкоды | LLM выдумывает границы | Передавать только существующие timestamps, валидировать JSON |
| Клип начинается без контекста | Hook находится раньше выбранной границы | `needs_context_before` и расширение интервала |
| Клип обрывается | Мысль продолжается в следующем окне | `continues_next`, `self_contained`, PASS 2 |
| Тишина в начале/конце | Нет padding | Добавлять 3 секунды до и 5 секунд после |
| Потеря качества | Лишний перекодированный кроп | Не использовать crop, рендерить в исходном разрешении |
| Слишком короткие клипы | Промпт ориентирован на Shorts | Минимум 120 секунд, цель 180 секунд |

## 22. Минимальный MVP

Для первой версии реализовать только это:

1. `yt-dlp` скачивает VOD.
2. `faster-whisper` делает транскрипт с word timestamps.
3. Скрипт режет транскрипт на окна по 150 секунд с overlap 30 секунд.
4. Ollama выполняет PASS 1 для каждого окна.
5. Скрипт объединяет последовательные окна с одинаковым `topic` и `continues_previous=true`.
6. Ollama выполняет PASS 2 и возвращает интервалы 120–300 секунд.
7. Скрипт убирает пересечения по IoU.
8. Человек получает Tkinter-таблицу с таймкодами, длительностью, оценкой, заголовком, обоснованием и транскриптом кандидата.
9. После утверждения FFmpeg вырезает исходное 16:9 видео без кропа.

Не добавлять в MVP:
- speaker diarization;
- генерацию thumbnail;
- автоматическую публикацию;
- сложные визуальные модели;
- ComfyUI;
- автоматические Shorts.

## 23. Критерии готовности MVP

Пайплайн считается рабочим, если:

- обрабатывает VOD длительностью 6–8 часов без ручного вмешательства до этапа ревью;
- находит минимум 10 кандидатов;
- большинство кандидатов имеют длительность 2–5 минут;
- темы длиной 10+ минут не разрезаются бессмысленно;
- LLM не выдумывает таймкоды;
- итоговые файлы остаются 16:9;
- человек может утвердить клипы за 10–20 минут;
- финальный рендер не меняет разрешение и не делает вертикальный кроп.

## 23. Ключевые места
двухпроходный map-reduce анализ, валидация таймкодов по транскрипту,
IoU-дедупликация и рендер без кропа. Map-reduce позволяет обрабатывать
очень длинные транскрипты по частям, а затем объединять промежуточные результаты

## 24. Уточнённый desktop-сценарий

- Пользователь вставляет YouTube URL и задаёт минимум/максимум длительности клипов в секундах.
- Приложение скачивает VOD, транскрибирует речь и предлагает непрерывные смысловые интервалы.
- Настройка длительности не означает механическую нарезку по фиксированному шагу.
- Анализ не запускает финальный рендер. Кандидаты сохраняются со статусом `pending`.
- В Tkinter доступны просмотр выбранного интервала через FFplay, текст, правка границ и заголовка,
  утверждение, отклонение и возврат на доработку.
- Финальная нарезка запускается отдельной кнопкой с подтверждением только для утверждённых интервалов.
- Код проверяет соответствие утверждения текущим границам. После изменения границ требуется новое утверждение.
- Сохраняется весь исходный горизонтальный кадр 16:9 и его разрешение, без кропа и растягивания.
- Тестовый VOD: https://www.youtube.com/watch?v=AVbz4UzkeTw (13602 с, 1280×720 по метаданным).
