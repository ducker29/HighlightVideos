# Задача: реализовать Subs Settings в HighlightVideos

Ты работаешь с существующим Python-проектом HighlightVideos — Windows-приложением с Tkinter GUI для создания Highlights и вертикальных Shorts из длинных видео.

Необходимо добавить полноценную кастомизацию оформления субтитров через отдельное окно **Subs Settings**.

Работай с реальной архитектурой проекта. Не предполагай заранее названия модулей, функций или формат конфигурации — сначала изучи код.

## 1. Обязательный аудит перед реализацией

Изучи:

- Главное окно приложения и его кнопки.
- Существующую реализацию рендера субтитров.
- FFmpeg filtergraph и способ передачи ASS/SRT.
- Текущие значения шрифта, размера, положения, фона и прозрачности.
- Настройки рендера Highlights и Shorts.
- Существующие механизмы сохранения конфигурации.
- Связь между GUI, backend и renderer.
- Существующие тесты субтитров и рендера.

Определи, какие настройки сейчас захардкожены, какие передаются через параметры и какие определяются стилями ASS.

**Важно:** не начинай реализацию, пока не установишь точные значения текущего оформления. Они должны стать значениями по умолчанию.

Если Highlights и Shorts используют разные стили, сохрани оба существующих стиля по умолчанию. Не унифицируй их ценой изменения текущего результата.

## 2. Кнопка в главном окне

Добавь кнопку:

**Subs Settings**

Требования:

- Кнопка находится в главном окне приложения.
- Открывает отдельное окно Tkinter `Toplevel`.
- Не блокирует основной интерфейс без необходимости.
- Не создаёт бесконтрольно несколько экземпляров окна.
- При повторном нажатии переводит существующее окно на передний план.
- Корректно закрывается без оставшихся Tkinter callbacks.
- Не затрагивает существующий Smart Crop Editor.

## 3. Окно Subs Settings

Создай отдельный модуль, например `subs_settings_window.py`, если это соответствует архитектуре проекта.

Окно должно содержать следующие настройки.

### A. Font

Выпадающий список шрифтов.

Требования:

- Показывать доступные в Windows шрифты.
- Отображать понятные пользователю названия.
- Сохранять выбранное семейство шрифта.
- Корректно обрабатывать отсутствие ранее выбранного шрифта.
- Не допускать падения приложения из-за отсутствующего шрифта.
- Проверить совместимость имени шрифта с ASS/libass.

### B. Font Size

Числовое поле и/или ползунок.

Требования:

- Пользователь может вручную задать размер.
- Значение проверяется перед сохранением.
- Не допускаются отрицательные, нулевые и некорректные значения.
- Размер должен соответствовать реальному масштабу субтитров при рендере.
- Учитывать особенности ASS PlayResX/PlayResY, если используется ASS.

### C. Position X

Свободная горизонтальная настройка положения.

Диапазон: **0–100% ширины итогового видео**.

- 0% — левая граница.
- 50% — центр.
- 100% — правая граница.

### D. Position Y

Свободная вертикальная настройка положения.

Диапазон: **0–100% высоты итогового видео**.

- 0% — верхняя граница.
- 50% — центр.
- 100% — нижняя граница.

Для X/Y:

- Использовать числовые поля и/или ползунки.
- Поддерживать дробные значения.
- Определить и задокументировать якорь позиционирования текста.
- Предпочтительно использовать центр текстового блока как якорь.
- Положение должно быть одинаково интерпретируемым при разных разрешениях.
- Учитывать размеры текста, перенос строк и границы кадра.
- Не допускать неконтролируемого выхода текста за экран.
- Если используются ASS-теги `\pos`, `\an` или другие механизмы позиционирования, обеспечить корректное экранирование и совместимость с текущим рендером.

Не заменять свободную настройку X/Y набором готовых позиций.

### E. Background Color

Выбор цвета фона субтитров.

- Использовать стандартный Tkinter color picker или подходящий существующий компонент.
- Поддерживать HEX-цвета вида `#RRGGBB`.
- Показывать выбранный цвет.
- Валидировать введённое значение.
- Не изменять цвет самого текста, если это не требуется существующей архитектурой.

### F. Background Opacity

Настройка непрозрачности фона.

Диапазон: **0–100%**.

- 0% — полностью прозрачный фон.
- 100% — полностью непрозрачный фон.
- Ползунок с отображением текущего значения.
- Правильно преобразовывать значение в формат FFmpeg/ASS.
- Учитывать, что альфа-канал ASS может иметь обратную семантику.
- Не путать прозрачность фона с прозрачностью текста.

Сохрани существующий тип фона субтитров. Если сейчас используется прямоугольная подложка, новая настройка должна менять её цвет и прозрачность, а не заменять другим визуальным эффектом.

## 4. Предпросмотр

Добавь область **Subtitle Preview** внутри Subs Settings.

Требования:

- Показывать пример текста, например «Пример субтитров».
- Отображать выбранный шрифт.
- Отображать размер текста.
- Отображать положение X/Y.
- Отображать цвет фона.
- Отображать прозрачность фона.
- Обновляться при изменении параметров без необходимости сохранения.
- Использовать область с пропорциями итогового видео, например 9:16 для Shorts.
- По возможности поддерживать переключение предпросмотра между форматами Shorts и Highlights, если они различаются.

Предпросмотр должен быть максимально близким к FFmpeg-рендеру.

Если Tkinter не позволяет точно воспроизвести поведение libass, не выдавай приближённый предпросмотр за пиксельно идентичный. Задокументируй ограничения.

Не запускай полный рендер видео для обновления предпросмотра.

## 5. Кнопки управления

В нижней части окна должны быть три кнопки.

### Save

Сохраняет текущие настройки.

Требования:

- Пользователь может выбрать путь и имя файла.
- Формат: JSON.
- Предусмотреть версию схемы.
- Сохранять все настраиваемые параметры.
- Выполнять валидацию перед записью.
- Использовать безопасную запись, желательно атомарную.
- Сообщать пользователю об успешном сохранении или ошибке.

**Важно:** сохранение настроек в JSON-пресет и применение настроек в приложении — разные действия.

Предусмотри понятное поведение: валидные изменения должны применяться к будущим рендерам после подтверждения пользователем, а Save дополнительно экспортирует их в файл.

### Load

Загружает ранее сохранённый JSON-пресет.

Требования:

- Диалог выбора файла.
- Проверка структуры и версии.
- Проверка всех значений.
- Понятная ошибка при повреждённом JSON.
- Не применять частично некорректные настройки.
- После загрузки обновлять все поля и предпросмотр.
- Загруженный пресет должен быть доступен для применения к будущим рендерам.

### Set Default

Возвращает все параметры к **текущему оформлению субтитров, которое существовало в HighlightVideos до этой задачи**.

Требования:

- Не использовать произвольные новые значения.
- Не брать значения из последнего пользовательского пресета.
- Восстанавливать реальные исторические значения проекта.
- Обновлять все поля и предпросмотр.
- Не удалять сохранённые JSON-пресеты.
- Не изменять существующие файлы пользовательских данных.

Если в приложении исторически разные стили Shorts и Highlights, восстанавливать соответствующие значения для каждого режима.

## 6. Применение настроек

Нужно, чтобы настройки действительно влияли на итоговый рендер, а не только на GUI.

Реализуй передачу настроек через существующую цепочку:

GUI → конфигурация/backend → renderer → FFmpeg.

Требования:

1. Все выбранные параметры должны применяться при следующем рендере.
2. Существующие проекты без пользовательских настроек должны продолжать рендериться с прежним оформлением.
3. Настройки должны сохраняться между перезапусками приложения.
4. Нельзя требовать повторного Whisper ASR, Ollama или анализа видео.
5. Изменения оформления должны применяться только на этапе рендера.
6. Не изменять тайминги субтитров, текст, сегментацию и синхронизацию речи.
7. Не изменять параметры Smart Crop.
8. Не ломать существующий Windows FFmpeg escaping для путей к файлам субтитров.
9. Учитывать субтитры из нескольких строк и длинные фразы.
10. Не изменять оригинальные SRT/ASS и существующие пользовательские файлы без явной необходимости.

Если для разных типов рендера используются разные механизмы субтитров, реализуй поддержку без скрытого изменения прежнего поведения.

## 7. Архитектура хранения настроек

Предпочтительно создать отдельный модуль управления настройками, например `subtitle_settings.py`.

В нём должны находиться:

- Модель настроек.
- Валидация.
- Значения по умолчанию.
- Сериализация в JSON.
- Загрузка JSON.
- Преобразование значений в формат рендера.

Раздели:

- Встроенные настройки по умолчанию.
- Активные пользовательские настройки.
- Экспортируемые/импортируемые пресеты.

Не привязывай renderer напрямую к Tkinter.

Не создавай глобальное изменяемое состояние, если существующая архитектура позволяет передавать настройки явно.

Продумай поведение при параллельных или уже запущенных рендерах: изменения настроек не должны непредсказуемо менять оформление в середине одного задания.

## 8. FFmpeg / ASS

Особое внимание удели корректной реализации.

Проверь:

- Правильный формат цветов.
- Преобразование HEX в формат ASS BGR.
- Инверсию alpha для ASS.
- Реальный размер шрифта.
- Поведение координат X/Y.
- Правильное экранирование ASS-тегов.
- Экранирование путей Windows.
- Сохранение текущих стилей текста, обводки, тени и переносов, если они существуют.
- Совместимость с текущим filtergraph.
- Отсутствие влияния на crop, scale, fps и timestamps.

Не заменяй существующий механизм субтитров целиком, если достаточно расширить его настройками.

Не делай предположений о поддержке параметров конкретной сборкой FFmpeg — проверяй реальные возможности.

## 9. Тестирование

Добавь автоматические тесты.

Минимально проверить:

**Настройки:**
- Корректные значения.
- Некорректный шрифт.
- Недопустимый размер текста.
- X/Y вне диапазона.
- Неправильный HEX.
- Неправильную прозрачность.
- Сохранение и загрузку JSON.
- Повреждённый JSON.
- Неизвестную версию схемы.
- Восстановление исторических defaults.

**GUI:**
- Открытие окна.
- Повторное открытие.
- Изменение параметров.
- Предпросмотр.
- Save / Load / Set Default.
- Закрытие окна без Tkinter callback errors.

**Renderer:**
- Правильное применение шрифта.
- Правильный размер.
- X/Y.
- Цвет фона.
- Alpha.
- Отсутствие изменений в старом рендере при отсутствии новых настроек.
- Корректные ASS/FFmpeg-аргументы на Windows.
- Отсутствие регрессий Smart Crop.

Если возможно, добавь короткий синтетический интеграционный FFmpeg-тест, проверяющий итоговое изображение с субтитрами.

Не используй длинные реальные видео для автоматических тестов.

## 10. Порядок выполнения

Работай по этапам:

1. Аудит текущей реализации.
2. Краткий план изменений и список файлов.
3. Реализация модели настроек.
4. Реализация окна Subs Settings.
5. Кнопка в главном окне.
6. Интеграция с backend и renderer.
7. Предпросмотр.
8. Тесты.
9. Проверка обратной совместимости.
10. Итоговый отчёт.

Не ограничивайся созданием GUI: задача считается выполненной только тогда, когда настройки применяются в реальном FFmpeg-рендере.

Если обнаружишь архитектурное препятствие, которое требует существенного переписывания пайплайна, остановись, объясни проблему и предложи минимальные варианты решения вместо большого рефакторинга.

## 11. Строгие ограничения

- Не изменять Smart Crop Editor и его логику.
- Не менять алгоритмы поиска Shorts.
- Не менять Highlights selection.
- Не менять Whisper/Ollama pipeline.
- Не запускать ASR или LLM.
- Не удалять пользовательские данные.
- Не очищать кэш.
- Не перезаписывать существующие видео.
- Не изменять Smart Crop JSON.
- Не проводить посторонний рефакторинг.
- Не менять зависимости без обоснованной необходимости.
- Не выполнять git commit или git push.
- Не использовать `git reset`, `git stash`, `git restore` или `git clean`.
- Сохранить все уже существующие незакоммиченные изменения.

Перед работой зафиксируй `git status --short`. После работы покажи итоговый diff и список изменённых файлов.

## 12. Критерии готовности

Задача выполнена, когда:

- В главном окне есть кнопка Subs Settings.
- Окно открывается и закрывается без ошибок.
- Пользователь может выбрать шрифт, размер, X/Y, цвет и непрозрачность фона.
- Работает предпросмотр.
- Работают Save, Load и Set Default.
- Активные настройки сохраняются после перезапуска.
- Изменения применяются к реальному рендеру.
- При Set Default результат соответствует прежнему оформлению субтитров.
- Старые проекты продолжают работать.
- Smart Crop не затронут.
- Все новые тесты проходят.
- Существующие регрессионные тесты не показывают новых ошибок.
